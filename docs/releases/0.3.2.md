# @at-series/mcp-hub 0.3.2 Release Notes

Version 0.3.2 adds Hub-local agent-ops audit logging and aligns installer / plugin-integration docs with the shipped behavior. Bridge wire stays `protocolVersion: 1`; Hub surface stays `2`.

## Highlights

### 1. Agent ops audit log

Every **business** `tools/call` (not the five Hub meta-tools) is appended as one JSON Line:

```text
~/.at-series/logs/<hostApp>/agent-ops-<YYYY-MM-DD>-<pid>.jsonl
```

- Default: enabled. Set `AT_SERIES_AUDIT_LOG=false` (also `0` / `off`) to disable.
- Retention defaults to 30 days (`AT_SERIES_AUDIT_RETENTION_DAYS`).
- Arguments and response previews redact exact sensitive keys and token-like substrings, then truncate large fields (prefix 1024 bytes + SHA-256).
- Writes are asynchronous (queue cap 100). A write failure does **not** change the MCP `tools/call` result.
- The installer does **not** write `AT_SERIES_AUDIT_*` keys, so Repair will not overwrite a user disable.

See [protocol/v1.md §3.4](../protocol/v1.md#34-agent-ops-audit-log-hub-local).

### 2. Documentation alignment

- Installer `autoApprove` is **Hub meta-tools only**; business tools (including `risk=read`) are not auto-approved.
- Plugin guide: `detectHostApp({ appName, appRoot, uriScheme, extensionPath })`, pack `hub.js` into the VSIX `dist/` at build time, `await syncHubBundle` before `ensureAtSeriesMcpConfig`, `uninstallAtSeriesMcpConfig`, Continue `workspaceFolder`.
- Installer writes `AT_SERIES_TOOL_SELECTION_IDLE_MS=0` (overrides the Hub runtime default of 30s).

## Migration

Plugins that still ship Hub **0.3.0** will not elect this bundle (lower semver never overwrites). Bump `@at-series/mcp-hub` to **0.3.2**, rebuild, and pack `dist/hub.js` so `syncHubBundle` records `version: 0.3.2`.

No Bridge HTTP or registry wire changes.
