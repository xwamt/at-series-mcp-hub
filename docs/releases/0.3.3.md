# @at-series/mcp-hub 0.3.3 Release Notes

Version 0.3.3 delivers major hot-path performance improvements across `tools/list` and `tools/call`, non-blocking cold startup, parallel bridge probing, memory catalog routing, and 15s selection winner grace during transient drops. Bridge wire remains `protocolVersion: 1`; Hub surface remains `2`.

## Highlights

### 1. Hot-path latency & memory catalog routing
- **`tools/call` routes from in-memory catalog** without paying a synchronous full network probe before each call (v1 §8.3.1). One on-demand refresh is performed only on a cache miss.
- **`tools/list` ≤2s TTL & coalescing**: Reuses the in-memory catalog when a refresh completed within the last 2 seconds (v1 §8.4, requirements D12/H9). Concurrent requests share an in-flight refresh.
- **Non-blocking cold startup**: `createHubRuntime` returns immediately and runs the baseline probe in the background; `initialize` handshake is no longer delayed by wedged bridges (v1 §8.1).
- **Parallel per-bridge probing**: `/health` and `/tools` are probed concurrently via `Promise.allSettled` (v1 §8.2).
- **Negative cache & backoff**: On-demand passes skip bridges whose last failure is newer than 4s; periodic timer skips healthy bridges probed within 15s.
- **Stale registry records**: Records older than 90s (three missed heartbeats) are skipped without HTTP probing (v1 §5).
- **Immediate demotion & failover**: Invoke transport failures demote the bridge in memory immediately and failover to the next candidate (v1 §8.3.5, §8.3.6).

### 2. Selection resilience & idle TTL
- **15s Winner Grace Window**: A selected tool that temporarily loses its bridge winner is retained for 15s of continuous absence before being pruned (v2 §4).
- **Default Idle TTL updated to 120s**: Aligned with the 120s `/invoke` confirmation ceiling; completing an invoke counts as selection activity (v2 §4.1).

### 3. Asynchronous audit & file I/O resilience
- **Audit redaction moved off response path**: Argument redaction and preview truncation run asynchronously within `AuditLogger` (v1 §3.4).
- **Dead-PID lock stealing**: `withFileLock` checks process liveness with `kill(0)` and reclaims locks left by crashed processes immediately (v1 §8.6).
- **Windows rename retries**: `atomicWriteFile` retries on `EPERM`/`EBUSY`/`EACCES`.
- **Directory fingerprint polling**: Registry watch polling checks name+mtime+size to avoid false `onChange` triggers.
- **BridgePublisher memory cache**: Skips redundant disk reads on periodic heartbeat writes.

### 4. Context & token footprint reduction
- **Compact JSON**: `at_list_providers` serializes compact JSON without whitespace indentation (v2 §3.1).
- **Search truncation**: `at_search_tools` truncates result previews to 120 chars; full text remains available in `at_get_tool` (v2 §3.2).

## Migration

No plugin code changes are required. Bump `@at-series/mcp-hub` to **`0.3.3`** across consumer plugins so `syncHubBundle` elects this runtime bundle.
