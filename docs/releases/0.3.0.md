# @at-series/mcp-hub 0.3.0 Release Notes

Version 0.3.0 is a major infrastructure, protocol hardening, and reliability release for `@at-series/mcp-hub`. It establishes strict outbound communication boundaries, cross-process concurrency safety, atomic configuration management, and timing side-channel defenses across the entire AT Series ecosystem.

## Highlights & New Features

### 1. Outbound Communication Sandboxing & Protocol Hardening
- **Redirect Refusal**: The Hub-to-Bridge client enforces `maxRedirections: 0`. Bridge HTTP endpoints MUST NOT return `3xx` redirects, and the Hub will immediately abort any redirect to prevent `x-at-series-token` or tool arguments from leaking to arbitrary hosts ([Protocol v1 §7.1](../../docs/protocol/v1.md)).
- **Response Size Ceilings**: Enforces `BRIDGE_MAX_BODY_BYTES` (2 MiB) on downstream Bridge responses. Oversized payloads are aborted mid-stream rather than buffered into memory.
- **Strict Deadlines**: `/tools` (5s) and `/invoke` (120s) requests are bounded with mandatory `AbortSignal` timeouts to prevent wedged Bridge servers from hanging MCP client interactions.
- **Parallel Bridge Probing**: Refreshes tool catalogs by probing registered Bridges concurrently while preserving stable registry file-order precedence for conflict resolution.

### 2. Cross-Process Concurrency & Bundle Integrity
- **Cross-Process File Locking (`withFileLock`)**: Synchronizes concurrent hub bundle election and configuration writes across multiple plugin startup processes using stale-aware `.lock` files.
- **Permission-Preserving Atomic Writes (`atomicWriteFile`)**: Writes to temporary staging files and executes atomic renames while enforcing strict POSIX permission modes (`0700` directories, `0600` files).
- **On-Disk SHA-256 Hash Verification**: `syncHubBundle` validates the real disk hash of `~/.at-series/mcp/hub.js` before skipping synchronization, preventing corrupted or outdated cached bundles.

### 3. IDE Configuration Safety & Comment Preservation
- **Non-Destructive Syntax Error Handling**: If user configuration files (`~/.cursor/mcp.json` or Continue configs) contain comments (`// ...`) or trailing commas that fail strict `JSON.parse`, the installer safely aborts without wiping user settings and provides actionable diagnostics.
- **Indentation & Format Sniffing**: Automatically preserves existing file formatting (2 spaces, 4 spaces, or Tabs) when injecting the `AT Series` entry.
- **Automatic Backup Generation**: Automatically creates `.bak` backups before modifying existing IDE configurations.

### 4. Protocol Utilities & Security Helpers
- **Constant-Time Token Comparison**: Exports `timingSafeEqualToken` and `createBridgeToken` to eliminate timing side-channel vulnerabilities during token verification.
- **Unified Host-App Detection**: Exports `detectHostApp`, `slugifyHostAppId`, and `DetectHostAppInput`, standardizing host environment identification across Cursor, Antigravity, VS Code, and JoyCode.
- **MCP Annotations Passthrough**: Maps tool `risk` attributes (`read`, `write`, `exec`) into standard MCP tool annotations (`readOnly`, `destructive`) for client-side policy evaluation.
- **Structured Diagnostic Logging**: Stderr logging via `AT_SERIES_LOG_LEVEL` with automated regex credential and token redaction.

## Migration Guide

- **Wire Protocol**: `protocolVersion` remains `1` for Bridge wire communication and `2` for Hub-to-IDE tool exposure.
- **Plugins**: Ensure Bridge servers answer `/health` and `/tools` within the recommended timeout ceilings and consume `timingSafeEqualToken` from `@at-series/mcp-hub`.
